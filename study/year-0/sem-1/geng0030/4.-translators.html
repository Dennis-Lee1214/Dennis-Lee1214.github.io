4. Translators

编程语言总体分类

层次 名称 例子 特点
高级语言 High-level High-Level Language C++，Java，Python 无需了解硬件，可移植（portable），可在不同系统使用
低级语言Low-Level Assembly Language X86,ARM,MIPS汇编 使用助记符mnemonic codes(MOV,ADD,SUB),与处理器架构相关，比机器语言可读性高，不占主存、执行快
低级语言Low-Level Machine Language 001011110..二进制 CPU直接执行的最基本形式，特定于处理器架构，需了解硬件细节制

什么是翻译器 Translator？

  • 将程序员写的高级/汇编语言代码翻译成计算机可理解的二进制形式的实用程序
  • 三种翻译器：Compiler编译器/Interpreter解释器/Assembler汇编器

三种编译器对比

编译器 Compiler

  • 将高级语言代码一次性全部翻译成机器码，生成可执行文件
  • 编译后可多次使用，无需重新编译。会对代码进行优化（optimise）。错误只在完整编译后才报告。编译后的代码难以反推回溯代码，难以修改
  • 源代码（source code）➡️目标代码（Object code），特定于硬件平台。不同平台需要不同编译器（如windows+Intel是一个平台，Apple+PowerPC是另一个平台）

解释器 Interpreter

  • 逐条语句读取高级语言代码➡️转为中间代码（汇编语言）➡️再转化为机器码➡️执行，然后处理下一条语句。
  • 遇到错误立即提示用户更正，不生成可执行文件。代码不会被优化
    源代码➡️中间代码➡️机器码➡️执行➡️

汇编器 Assembler

  • 将汇编语言翻译成机器码。有时先翻译成中间代码字节码（bytecode）。汇编后可多次使用，无需重新汇编。输入称为源代码，不同处理器架构有不同汇编指令

三种翻译器对比

特点 Complier 编译器 Interpreter 解释器 Assembler 汇编器
执行方式 一次性翻译全部代码 逐行翻译执行 将汇编代码翻译为机器码
输出 生成可执行文件 不生成可执行文件 直接生成机器码
执行速度 编译后更快 较慢（逐行执行） 取决于硬件
错误报告 完整编译后才报告所有错误 每遇错误立即停止并报告 转换完成后报告错误

字节码与JVM

字节码 Bytecode 是什么？

  • 介于编译和解释之间的中间表示形式，使程序可移植（portable）、平台无关（Platform-independent）。只要目标系统安装了对应的虚拟器，即可运行
  • 使用字节码的语言：Java，Python，MATLAB等。

Java的流程

  • Java源代码（.Java）--编译Compile--字节码(.class文件)--JVM执行--本地机器码

Python的流程

  • Python源代码（.py）--编译--字节码(.pyc文件)--Python解释器执行--运行结果

Java虚拟机JVM的优点

  • 机器无关性(Machine independence):字节码可在任何安装了JVM的系统上运行
  • 安全性增强：来自未知来源的字节码先在JVM中运行，确认无恶意后才运行主程序

编译阶段：词法分析

编译的三个阶段 Stages Compilation

  • 词法分析Lexical Analysis--语法&语义分析Syntax & Semantic--代码生成&优化Code Generation

词法分析Lexical Analysis - 功能

  • 删除注释（#或//开头）和多余空格。例：num = int(input(...)) -- num = int(input())
  • 检查非法标识符。例：Python变量名不能以数字开头，2num会被标记为非法
  • 检查非法常量值（如类型不匹配），会产出溢出overflow或下溢underflow错误
  • 将关键字，常量，变量替换为唯一符号--Token（标记）。标识符被替换为指向变量地址的指针；关键字(print等)替换为项目项目代码item codes

符号表 Symbol Table

  • 存储源代码中所有关键字、变量、常量的详细信息。每条记录包含：
字段 内容
Kind 种类 变量、关键字、常量、过程、函数或数组
Data type 地址类型 Float, int, char, string, date, Boolean
Address/Valuen地址或值 运行时地址或常量值
数组边界 Bounds 数组索引必须在边界内
参数信息 过程/函数的参数数据类型

例：Area = width height 的符号表中Area/width/height为float类型变量, =和为运算符。

标记化 Tokenisation

  • 符号表创建后，每个项目被标记化。例：Area = width * height 可被标记为7 1 2 3 6. 词法分析器填写名称和地址/值列；语法分析器在下一阶段填写种类和类型列。

哈希表 Hash Table

  • 用于存储符号表的数据结构。元素以数组形式排列，下标通过哈希函数（Hash function）计算。编译器在标记化过程中多次访问符号表，哈希确保更快的处理速度

编译阶段：语法与语义分析

语法分析 Syntax Analysis

  • 判断token序列是否符合该语言的有效语法规则
  • 解析Parsing：通过一套规则判断条件语句是否有效
  • 括号配对检查：用栈stack验证括号是否正确配对
  • 运算符分析与优先级排序。将表达式转化为便于生成机器码形式
  • 常见语法错误Syntax Errors：括号未配对/缺少分号/错误缩进/语句结构不正确

语义分析 Semantic Analysis

  • 语法Syntax = 语言的语法规则。语义 Semantics = 语言的含义
  • 常见语义错误Semantic Errors：
    • 使用未声明的变量（在某些语言中）
    • 类型不匹配的错误：把实数赋值给整数变量
    • 用实数值作为循环计数器

注意：语法正确不代表语义正确，例：print（num1）语法错误，但如果num1未定义，则是语法错误

编译阶段：代码生成与优化

代码生成与优化Code Generation & Optimisation

  • 编译的最后阶段，生成机器码
  • 代码优化技术 ：减少执行时间和资源消耗。方法：删除冗余指令、改变程序运行方式（但结果相同）
  • 例：将循环内部赋值语句移到循环外部，避免重复执行相同语句

注意：某些优化可能导致程序产生错误结果。优化有时也会增加编译时间

DLL，链接器与加载器

动态链接库DLL（Dynamic Linked Libraries）

  • 子程序的共享库。程序员在程序中需要时随时调用这些子程序，无需重新编写
  • 某些程序员频繁使用的例程序被开发并测试后存入库中。调用例程的语句被翻译时，代码库中取出并执行。多个程序可共享同一个DLL

链接器 Linker

  • 主程序编译后，已编译的子程序必须与机器码链接，这由链接器完成
  • 当子程序被调用时，call和return语句在主程序和子程序之间转移控制权。链接器的功能：在call和return语句提供机器地址，确保所有模块正确链接在一起

加载器 Loader

  • 重定位加载器（Relocating Loader）：将目标代码加载到内存中的任意位置
  • 运行条件：
    1. 程序不得包含绝对地址
    2. 程序必须是可重定位格式

完整编译流程

源代码(HLL) -- 翻译器 Translator -- 机器码 -- 链接器 Linker -- 可执行文件 -- 加载器 Loader -- 内存 Memory
